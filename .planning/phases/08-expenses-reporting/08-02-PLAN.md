  <action>
    Create `resources/js/components/reports/DateRangeControl.vue`. This component owns NO routing/navigation — it only computes concrete dates and emits them; the parent page (Task 2 here, and Plan 08-05 later) performs the actual `router.get()`.

    Props: `defineProps&lt;{ from: string; to: string }&gt;()` (ISO `YYYY-MM-DD` strings — the currently-applied range, used to determine which preset button, if any, is active). Emits: `defineEmits&lt;{ apply: [payload: { from: string; to: string }] }&gt;()`.

    Five preset `Button`s in an `sm` (8px) gap row: "Today", "This Week", "This Month", "This Quarter", "Custom". Compute each preset's concrete range client-side on click and emit `apply` immediately (one click = one `apply` event, no second confirm step) for every preset except "Custom":
    - Today: `from = to = new Date().toISOString().slice(0, 10)`
    - This Week: `from` = the Monday of the current week (`date.getDay()` treating Sunday=0 as 7 days back to the prior Monday), `to` = today
    - This Month: `from` = the 1st of the current month, `to` = today
    - This Quarter: `from` = the 1st day of the current 3-month quarter (`Math.floor(month / 3) * 3`), `to` = today

    Selecting "Custom" does NOT emit `apply` immediately — it reveals two `Input type="date"` fields (`w-40`, matching `PerformanceReport.vue`'s exact class) labelled "From"/"To", plus an "Apply Range" `Button` that emits `apply` with the two field values on click.

    Active-preset detection: compare the `from`/`to` props against each preset's own computed range; whichever preset's computed range exactly matches the props gets `variant="default"`, all others `variant="outline"` — if none match, no preset is highlighted and the "Custom" fields are shown pre-filled with the current `from`/`to` props (this is the state after a custom range has been applied). Beneath the buttons, render "Showing {range label}" (`text-muted-foreground`, Body) where the range label uses `en-PH`, `{ month: 'short', day: 'numeric', year: 'numeric' }` formatting, joined with " – " (en-dash, spaced) for a multi-day range, or a single date when `from === to`.

    Validation: if a Custom "To" precedes "From", or either date is in the future, do not emit `apply` — instead show the exact copy from the UI-SPEC's Date range control table ("The end date can't be earlier than the start date." / "Pick a date on or before today.") beneath the fields in `text-destructive`, matching the project's existing inline-error convention (no `InputError` component needed here since this isn't bound to a server-validated Form).
  </action>

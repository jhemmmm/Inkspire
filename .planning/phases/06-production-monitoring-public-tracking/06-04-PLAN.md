<objective>
Wire the automatic, no-manual-step entry into production (D-08) that PROD-01/PROD-02 depend on: the moment a Type A job order's file validates, or a Type B job order's design is approved (by either of Phase 4's two independent approve() paths), it immediately and automatically becomes `ForProduction` with a stamped `due_at` and a system-authored first `production_logs` row (D-06, D-09). Because this changes what status a "payable" job order sits at, this plan also fixes the three Cashier-side status gates (pricing, payment, credit request) and the Cashier Dashboard listing query so they keep working once orders move past `ReadyForProduction`/`DesignApproved` — a correctness requirement, not new scope, since Phase 5 D-15 already established that payment must never be blocked by production progress. It also fixes one more same-file consequence of the same wiring: `QueueEntryController::addJobOrder()`'s post-outcome toast message, which would otherwise throw for a Type A file that passes validation.

Purpose: Without this plan, no job order would ever observably sit at `ForProduction`/`Printing`/etc. long enough for the Production Board (built next) to have anything real to show, and Cashier would silently lose the ability to price/pay/credit-request any order the instant it entered production.
Output: `EnterProduction` action wired into all four status-transition call sites; three Cashier controllers accept the new production-track statuses; two pre-existing tests updated to reflect the new terminal status; `addJobOrder()`'s toast-message match extended so it doesn't throw.
</objective>

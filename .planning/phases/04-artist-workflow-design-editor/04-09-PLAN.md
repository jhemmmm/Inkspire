## Phase Goal

**As an** Artist, **I want to** take a Type B job order from consultation through a locked, approved design, **so that** the job order becomes ready for pricing at the Cashier and production never depends on an unfinished or unapproved design.

<objective>
Build JOB-10's performance report: jobs completed, average revisions per job, and SLA adherence over a selectable date range, computed entirely from data this phase already produces (`job_orders`, `revision_logs`) plus Phase 1's existing `default_sla_days` system config — no new library, no new config key.

Purpose: This is the last piece of data the Artist portal needs; it has no functional dependency on Plans 04-04/04-05/04-06/04-08's UI work, only on the schema those plans' sibling backend plans (04-03, 04-07) already shipped. It sequences after Plan 04-07 because both plans append routes to the same `routes/portals.php` `artist.` group, not because of any business-logic dependency.
Output: `PerformanceReportController`, `PerformanceReportFilterRequest`, and full Pest coverage of the aggregation logic.
</objective>

    Create app/Http/Controllers/Artist/PerformanceReportController.php. Public method `index(PerformanceReportFilterRequest $request): Response`. Resolve `$from = $request->date('from');` and `$to = $request->date('to');`. Query the artist's completed job orders: `JobOrder::query()->where('assigned_artist_id', $request->user()->id)->where('status', JobOrderStatus::DesignApproved->value)->withCount('revisionLogs')->with(['revisionLogs' => fn ($query) => $query->where('outcome', 'approved')->latest('reviewed_at')->limit(1)])->get(['id', 'created_at', 'assigned_artist_id', 'status'])`. This gives every `design_approved` job order for this artist with its revision count and its single approving revision eager-loaded (D-16 — "jobs completed" means reached `design_approved`, and the approving revision's `reviewed_at` is the actual completion timestamp, not `job_orders.created_at`).

    Filter that collection in PHP (not SQL — this shop's scale makes a collection filter simpler than a correlated subquery): `->filter(function (JobOrder $jobOrder) use ($from, $to) { $approvedAt = $jobOrder->revisionLogs->first()?->reviewed_at; if ($approvedAt === null) { return false; } if ($from !== null && $approvedAt->lt($from)) { return false; } if ($to !== null && $approvedAt->gt($to->copy()->endOfDay())) { return false; } return true; })`.

    Compute: `$jobsCompleted = $completed->count();`, `$avgRevisions = $jobsCompleted > 0 ? round($completed->avg('revision_logs_count'), 1) : 0;`, `$slaDays = SystemConfiguration::getInt('default_sla_days', 3);`, `$withinSla = $completed->filter(fn (JobOrder $jobOrder) => $jobOrder->created_at->diffInDays($jobOrder->revisionLogs->first()->reviewed_at) <= $slaDays)->count();`, `$slaAdherence = $jobsCompleted > 0 ? (int) round(($withinSla / $jobsCompleted) * 100) : 0;`.

    Render `Inertia::render('artist/PerformanceReport', ['stats' => ['jobsCompleted' => $jobsCompleted, 'avgRevisions' => $avgRevisions, 'slaAdherence' => $slaAdherence], 'filters' => $request->only(['from', 'to'])])`.

    Edit routes/portals.php: import `App\Http\Controllers\Artist\PerformanceReportController`. Inside the `artist.` group, add `Route::get('performance-report', [PerformanceReportController::class, 'index'])->name('performance-report.index');`. Run `php artisan wayfinder:generate --with-form --no-interaction`.

    Write tests/Feature/Artist/PerformanceReportTest.php: "performance report shows zero stats for an artist with no completed job orders" (`stats.jobsCompleted === 0`, `stats.avgRevisions === 0`, `stats.slaAdherence === 0`); "counts a design_approved job order with an approved revision log as completed" (build via `JobOrder::factory()->assignedTo($artist)->create(['status' => 'design_approved'])` + `RevisionLog::factory()->for($jobOrder)->approved()->create()`); "excludes a completed job order whose approved reviewed_at falls outside the requested from/to range" (pass `from`/`to` query params that exclude it); "average revisions per job averages revision_logs count across completed job orders" (one completed job order with 1 revision_logs row, another with 3, assert avgRevisions is 2.0); "sla adherence reflects the percentage of completed job orders approved within default_sla_days" (one job order whose approving revision's reviewed_at is 1 day after created_at, one whose is 10 days after, against the seeded default_sla_days of 3, assert slaAdherence is 50); "an artist's performance report never counts another artist's completed job orders".

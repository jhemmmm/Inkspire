<objective>
Close the single BLOCKER gap recorded in 04-VERIFICATION.md (elevated from 04-REVIEW.md's CR-01): `RecordDesignRevision::__invoke()` dispatches `Mail::to(...)->send(new DesignReviewRequested(...))` synchronously and unguarded, strictly after its `DB::transaction()` has already committed the design file save, revision log, and `job_orders.status` advance to `pending_review`. Because `.env`/`.env.example` declare `MAIL_MAILER=resend` as the app's real mail transport, any transport failure (bad/expired `RESEND_API_KEY`, a Resend outage, a rejected recipient) throws uncaught, past the point where the Artist's success toast would have flashed — the Artist sees a broken save even though their action fully succeeded, and `DesignEditorController::sendForReview()`'s own "already pending" 422 guard then blocks any retry.

Purpose: Make Send for Review — the single most central Artist action in this phase, and the action JOB-05 exists to describe — resilient to mail transport failures, so a real Resend hiccup can never corrupt the Artist's outcome.

Output: `RecordDesignRevision.php`'s mail dispatch wrapped in try/catch + `report($e)` (the codebase's first outbound email, greenfield, no queue-worker precedent to lean on — see task action for why this is chosen over `ShouldQueue`), plus a regression test proving the Artist's "Send for Review" request still succeeds end-to-end when the mail transport throws.
</objective>

  <action>
    In app/Actions/JobOrder/RecordDesignRevision.php, wrap the existing post-commit mail dispatch line in a try/catch: `try { Mail::to($jobOrder->queueEntry->customer->email)->send(new DesignReviewRequested($revisionLog)); } catch (\Throwable $e) { report($e); }`. Wrap the whole `Mail::to(...)->send(...)` expression (not just `send()`), so a failure resolving `queueEntry`/`customer`/`email` is caught too, not only a transport-layer throw. `report()` is a global Laravel helper (no import needed) that dispatches to the bound exception handler's `report()` method — this is exactly what `Exceptions::fake()`/`Exceptions::assertReported()` intercepts in the test. Do not add `ShouldQueue` to `DesignReviewRequested` — see read_first for why (phpunit.xml's `QUEUE_CONNECTION=sync` and the absence of any queue-worker precedent in this codebase mean `ShouldQueue` alone would not deterministically close this gap; try/catch protects the Artist's response under every queue configuration, including production's `database` driver). Update the method's docblock (currently describes the D-18 post-commit email ordering) to add one sentence: mail delivery failure is caught and reported, never allowed to fail the write, since the transactional core already committed.

    In tests/Feature/Artist/SendForReviewTest.php, add `use Illuminate\Support\Facades\Exceptions;` and `use Illuminate\Support\Facades\Mail;` to the top imports, then add the new test described in `<behavior>` above, placed after the existing "sending a design for review from in_consultation..." test (around line 61) so it sits next to its closest analog.

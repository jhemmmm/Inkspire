## Phase Goal

**As an** Artist, **I want to** take a Type B job order from consultation through a locked, approved design, **so that** the job order becomes ready for pricing at the Cashier and production never depends on an unfinished or unapproved design.

<objective>
Add JOB-08's session-status machinery: a 3-state `artist_status` enum plus `break_started_at`, kept in lockstep with the existing `is_available` boolean so Phase 3's round-robin query needs zero changes (D-13). This plan is backend-only and has no functional dependency on Plans 04-04/04-05's design-editor work — it shares files with earlier plans only incidentally (`routes/portals.php`, `JobOrderQueueController.php`).

Purpose: D-13's whole point is that `is_available` stays queryable exactly as `AssignArtistToJobOrder` already expects it — this plan proves that by wiring the existing (previously caller-less) `claimOldestUnassigned()` method for the first time.
Output: `ArtistStatus` enum, `SetArtistSessionStatus`, `SessionStatusController`, the Dashboard's `artistStatus` prop, and the Owner-facing `exceeded_break_time` indicator.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Authenticated Artist -> own session-status endpoints | No route parameter — the action always targets `$request->user()`, so an Artist can never change another artist's session status |
| Owner-facing exceeded-break computation -> client | Server computes the boolean; the client never receives a raw timestamp to do its own (clock-skew-prone) elapsed-time math |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-04-18 | Elevation of Privilege | app/Http/Controllers/Artist/SessionStatusController.php | mitigate | Every method operates on `$request->user()` only — there is no route-bound target user, so there is no ownership check to bypass |
| T-04-19 | Tampering | app/Http/Controllers/Artist/SessionStatusController.php | mitigate | Each transition guards its required source state (`abort_unless`) — a client cannot start a break while already on break, or end a shift twice |

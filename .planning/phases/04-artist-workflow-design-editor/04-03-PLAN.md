## Phase Goal

**As an** Artist, **I want to** take a Type B job order from consultation through a locked, approved design, **so that** the job order becomes ready for pricing at the Cashier and production never depends on an unfinished or unapproved design.

<objective>
Build the backend contract the TOAST UI editor (Plan 04-04) mounts against: the `design_files`/`revision_logs` schema, the `InDesign`/`PendingReview`/`DesignApproved` status cases (all three added here so Plan 04-05's review/lock/override work never has to touch `JobOrderStatus.php` again), the `RecordDesignRevision` transaction, the `startDesign` state-machine entry point, and the `sendForReview` endpoint with its lock and resubmission guards. This plan runs in parallel with Plan 04-02 (no shared files) and is itself backend-only — no canvas, no npm packages, no Vue.

Purpose: JOB-06's "read-only once approved" requirement only works if the lock check has a single, independent source of truth. Per 04-RESEARCH.md's Open Question #2, that source is `design_files.locked_at` — not `job_orders.status` — so that Plan 04-05's Owner unlock override can clear the lock without also having to roll back the job order's review status. Getting this modeled correctly here means Plan 04-05 only has to flip `locked_at`, nothing else. Separately, D-06's literal `InDesign -> PendingReview -> DesignApproved` cycle only holds meaning if `InDesign` is an observable status the job order actually passes through on its first design pass, not just on the change-request bounce-back Plan 04-05 adds — `startDesign` is that first-pass entry point.
Output: Two new tables/models/factories, three new `JobOrderStatus` cases, `RecordDesignRevision`, `DesignEditorController::startDesign`/`sendForReview`, and the `JobOrderWorkspaceController::show()` prop extension the design editor reads.
</objective>

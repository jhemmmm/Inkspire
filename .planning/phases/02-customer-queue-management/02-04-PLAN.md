Deliver the internal, authenticated counterpart to the public queue display: a Frontline Staff view of today's queue with the manual Waiting -> Serving -> Done workflow (D-05/D-08), plus the dedicated "add a job order to an existing visit" action that makes D-15's "visits are never locked, even when Done" guarantee actually usable rather than just a data-model statement (D-18).

Output: `QueueEntryController::index/callNext/markDone/addJobOrder`, the routes for each, and `QueueList.vue` — a new Frontline Staff nav destination.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser (authenticated Frontline Staff) -> status-transition routes | A direct PATCH request could attempt to skip a stage even if the button that would trigger it isn't rendered client-side |
| Browser -> `addJobOrder` route | No temporal/status restriction is intentional here (D-15) — must not be accidentally re-introduced as a "fix" later without revisiting the locked decision |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-02-12 | Tampering (state-machine bypass) | `QueueEntryController::callNext`/`markDone` | mitigate | Each method's `abort_unless()` re-checks the current DB status server-side before transitioning — hiding the button client-side is a UX nicety, not the security control |
| T-02-13 | Information Disclosure | `QueueEntryController::index` | accept | Exposing `customer.name` here is intentional and locked (D-05: "PII is fine here since it's role-gated") — contrast with the public display in Plan 02-05, which must never do this |
| T-02-14 | Tampering (unrestricted mutation) | `QueueEntryController::addJobOrder` | accept | Deliberately has no status/date precondition per D-15/D-18 — any existing `queue_entries` row (route-model-bound, so it must exist) can receive a new job order regardless of state; this is the locked business rule, not an oversight |
</threat_model>

<objective>
Build the backend half of Phase 2's second vertical slice: generating a queue number for a visit and saving one-or-more job orders (each Type A or Type B) in a single atomic save. This plan is deliberately backend-only — the concurrency-safe daily counter, the nested-array file validation, and the transactional multi-row insert are one tightly-coupled unit of business logic that cannot be safely reviewed or tested piecemeal, and combined with the UI wiring in one plan would push a single agent past a safe context budget. Plan 02-03 (next, same wave-chain) immediately wires the UI on top of the endpoint this plan ships, completing the user-observable slice.

Purpose: QUEUE-03/04/05 all hinge on one non-obvious correctness property — two Frontline Staff terminals generating a number in the same instant must never collide — and Laravel/MySQL only guarantee that under `lockForUpdate()` inside a transaction (RESEARCH.md Pattern 1). Getting this right, with its own dedicated Pest coverage, before any UI depends on it, is the point of this plan.
Output: `queue_entries`/`job_orders` tables + models + enums + factories, `QueueEntryController::store()` (the combined transactional intake endpoint), and Pest coverage for the counter's sequential correctness, the atomic multi-row save, the Type A/B conditional file requirement, and the audit_trail rows both new models must write.
</objective>

## Trust Boundaries

| Boundary                                                               | Description                                                                                              |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Browser (authenticated Frontline Staff) -> QueueEntryController::store | Untrusted nested-array + file upload input; must never let the client dictate `queue_number` or `status` |
| Concurrent requests -> `queue_entries` table                           | Two simultaneous requests racing to generate "the next" number for the same business day                 |
| Uploaded file -> filesystem                                            | Client-controlled filename/content must never determine the stored path or be trusted as safe            |

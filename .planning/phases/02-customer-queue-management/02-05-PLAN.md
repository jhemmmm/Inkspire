<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Anonymous internet client -> `queue-display` route | The only route in the entire application reachable without any authentication; the sole security control is what the controller chooses to expose |
| Anonymous polling client -> repeated GET requests | By design, this route is hit repeatedly (every 5s) for as long as the page is open |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-02-15 | Information Disclosure (critical — this is the highest-scrutiny route in the phase) | `app/Http/Controllers/Public/QueueDisplayController.php` | mitigate | Explicit `->select(['id', 'queue_number', 'status'])`; never eager-loads or references the `customer` relation or `customer_id` column; proven by `tests/Feature/Public/QueueDisplayTest.php`'s raw-content string assertion that no seeded customer name ever appears in the response body — not just a props-shape assertion, which could theoretically miss a leak elsewhere in the payload |
| T-02-16 | Denial of Service | Repeated unauthenticated polling / scripted abuse | mitigate | `throttle:60,1` middleware on the route — comfortably covers one legitimate client polling every 5s (12 req/min) while capping abuse from a single source |
| T-02-17 | Tampering | N/A | accept | Read-only `GET`, no mutation surface exists on this route at all |
| T-02-18 | Spoofing | N/A | accept | No authentication boundary exists to spoof — the route is intentionally public by design (D-09) |
</threat_model>

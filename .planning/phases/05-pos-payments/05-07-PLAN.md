Resolve this by running `php artisan make:migration add_released_at_to_job_orders_table --no-interaction`, then implementing it to add a `released_at` timestamp nullable column via `Schema::table('job_orders', ...)`, plus a matching `released_at` cast (`'datetime'`) added to `app/Models/JobOrder.php`'s existing `casts()` method — this is the correct minimal fix rather than skipping release-tracking entirely, since POS-09's "cannot be released... otherwise redirected to Cashier" implies a real one-time action, not a repeatable no-op.

    Run `php artisan make:controller FrontlineStaff/JobOrderReleaseController --no-interaction`, then implement it — `public function store(ReleaseJobOrderRequest $request, JobOrder $jobOrder): RedirectResponse`. This is the single, only place POS-09's gate is enforced — it must re-check `payment_status` itself, never trust that the UI only shows the button when eligible (RBAC-02 precedent, RESEARCH.md's explicit anti-pattern callout).     If `$jobOrder->payment_status === PaymentStatus::Paid || $jobOrder->payment_status === PaymentStatus::OnCredit`: `$jobOrder->forceFill(['released_at' => now()])->save();` flash `"Released to customer."` `return back();`

    If `$jobOrder->payment_status === PaymentStatus::CreditPendingApproval`: `return back()->with(['toast' => ['type' => 'error', 'message' => __("This job order's On-Credit request is still pending Owner approval. Send the customer to Cashier.")]]);` (or use the existing `Inertia::flash('toast', [...])` convention instead of `->with()` — match whichever mechanism this codebase's error-toast convention actually uses, confirmed via `bootstrap/app.php`'s 422-exception-to-toast bridge; simplest correct approach is to `abort_if` with a 422 message and let the existing global exception handler in `bootstrap/app.php` convert it to the flashed error toast automatically, exactly like every other `abort_unless`/`abort_if` in this codebase already does — prefer this over a bespoke `->with()` call for consistency).

    For every other `payment_status` value (`Unpaid`, `PartiallyPaid`, `PendingConfirmation`, `CreditRejected`): `abort_if(true, 422, __("This job order isn't fully paid yet. Send the customer to Cashier before releasing it."));` — both blocked-message variants route through the same `abort_if(..., 422, $message)` → global-handler → flashed-error-toast path already established by every other guarded controller action in this codebase (`DesignEditorController`, `QueueEntryController`, etc.); do not invent a new response-shaping mechanism for this controller.

    Modify `routes/portals.php`'s existing `role:frontline_staff` group: add `Route::post('job-orders/{jobOrder}/release', [JobOrderReleaseController::class, 'store'])->name('job-orders.release');`.

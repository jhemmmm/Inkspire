<objective>
Let Cashier or Accounting Staff manually check a stalled GCash/Maya payment against PayMongo when the webhook hasn't arrived (POS-04, D-12), reusing Plan 05-03's `ConfirmPaymentIntent` action as the single confirmation path so a webhook arriving mid-reconciliation (or vice versa) can never double-credit.

Purpose: The webhook usually resolves pending payments automatically, but this manual fallback is what makes the GCash/Maya path trustworthy enough to rely on operationally. It also completes D-11's non-blocking design: because Plan 05-01's Cashier Dashboard never locks the register on a single pending transaction, a job order simply sits in the 'awaiting confirmation' list (this plan's Accounting Staff Dashboard, and the same filter on Cashier's own Dashboard) until the webhook or this manual check resolves it.
Output: `ReconciliationController` mounted for both roles; the QR sub-view's "Check Payment Status" button wired; Accounting Staff's first real dashboard.
</objective>

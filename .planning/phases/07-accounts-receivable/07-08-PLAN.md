<objective>
Terminate the AR-04 write-off/settlement-integrity defect class that rounds 07-06 and 07-07 each partially closed but did not exhaust. Both prior rounds fixed exactly the files their own findings named and stopped; the next verification round found the neighbouring unguarded file. This round plans against the orchestrator's complete, finite, pre-enumerated surface instead of against a findings list: six `payment_status` mutators and seven copies of the same derived-balance computation across three files.

Purpose: (1) collapse the duplicated derived-balance computation into one place on `JobOrder` so future terminal-state guards have exactly one thing to call, removing the structural reason the last two rounds kept missing files; (2) guard every remaining unguarded or partially-guarded `payment_status` writer (`CreditApprovalController`, `PaymentController`'s `CreditPendingApproval` gap, and the previously-deferred `ConfirmPaymentIntent`); (3) close the two AR-03 controllers (`CollectionStatusController`, `CollectionLetterController`) that were never touched by either prior round despite sharing the identical fault line; (4) give an approved On-Credit balance a reachable payment path in the Cashier Dashboard, so "tracked ... through ... collections" is actually true and write-off is not the only reachable terminal state.

Output: one new model method (`JobOrder::outstandingBalance()`) wired through eight call sites, three new/extended terminal-state guards (`CreditApprovalController::approve()`, `PaymentController::store()`/`edit()`, `ConfirmPaymentIntent`), two AR-03 controller hardenings (`CollectionStatusController`, `CollectionLetterController`), one Cashier Dashboard UI fix, regression tests proving each fix against real triggering conditions, and a final grep-based audit proving the enumerated surface is exhausted.

**Scope discipline:** this plan touches exactly the files listed in frontmatter. It does not add a service class, state machine, new enum, or new migration. Every guard is an additive `abort_if`/`abort_unless` matching the exact style 07-06/07-07 already established. `WriteOffRequestController::store()`'s own unlocked-read defect (WR-07, smaller blast radius, a request only records a reason) and the reminder-command warnings (WR-01/WR-02/WR-03) stay explicitly out of scope -- they are not part of the four mandatory items this round closes and are not on the six-mutator/seven-copy enumerated surface.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `owner.write-off-requests.approve` / `.reject` | Owner-authenticated mutations on a receivable already marked as a booked financial loss |
| `cashier.job-orders.cancel` | Cashier-authenticated mutation that can reverse a written-off job order's terminal state via a cancellation fee transaction |
| `cashier.job-orders.payment.store` | Cashier-authenticated mutation that can reverse a written-off job order's terminal state by recording a new payment |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-06-01 | Tampering | `WriteOffApprovalController::reject()` | mitigate | `abort_if(collection_status === WrittenOff)` guard, mirroring `approve()`'s existing terminal-state check -- an already-approved write-off's reason/requester/timestamp can never be nulled by a stale or replayed Reject click (CR-01) |
| T-07-06-02 | Tampering / Denial of Service (workflow) | `WriteOffApprovalController::approve()` / `index()` | mitigate | `approve()` nulls `write_off_requested_at` on success; `index()` independently excludes `paid`/`written_off` `collection_status` rows -- an approved entry cannot masquerade as still-pending in the Owner's queue (CR-02) |
| T-07-06-03 | Tampering (business-logic reversal) | `CancellationController::store()` | mitigate | `abort_if(payment_status === WrittenOff)` added alongside the existing `Paid`/`PendingConfirmation` guards -- a booked loss cannot have a cancellation fee charged against it, and `cancelled_at` cannot be set on it (CR-03) |
| T-07-06-04 | Tampering (business-logic reversal) | `PaymentController::store()` | mitigate | `abort_if(payment_status === WrittenOff)` added alongside the existing `Paid` guard, checked before the GCash/Maya branch -- a booked loss cannot be paid back to `paid`/`partially_paid`, which would desynchronize the job order from the AR entry's `written_off` `collection_status` (CR-03) |
| T-07-06-05 | Information Disclosure / UI-Server Mismatch | `resources/js/pages/cashier/Dashboard.vue` | mitigate | The Cancel Job Order action is no longer rendered for `written_off` job orders, so the Cashier UI never offers an action the server-side guard (T-07-06-03) would now reject with a 422 |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inline padding |
| sm | 8px | Compact form field gaps (matches existing `gap-2` in `Login.vue`) |
| md | 16px | Default element spacing, card padding, table cell padding |
| lg | 24px | Section padding within a portal page |
| xl | 32px | Layout gaps between major page regions (sidebar content offset) |
| 2xl | 48px | Major section breaks (e.g. between config groups on System Configuration page) |
| 3xl | 64px | Page-level top/bottom spacing on full-page auth screens |

Exceptions: Interactive row-level controls in the audit trail table (filter chips, per-row expand) use a 40px minimum touch/click target height (existing shadcn `Button`/`Input` default height, `h-9`/`h-10`) even though 40 is not on the 8-point scale — this matches the already-installed component defaults and is not overridden.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

- Body (14px/400/1.5): form input text, table cell values, audit log entry descriptions, helper/description text.
- Label (14px/600/1.4): form field labels, table column headers, badge text, nav item text.
- Heading (20px/600/1.2): section headings within a page (e.g. "Audit Trail", "Business Rules", "Session & Lockout Policy").
- Display (28px/600/1.2): page-level title per portal (e.g. "Owner Dashboard", "System Configuration", "Audit Trail").

Only two weights used across the phase: 400 and 600. Do not introduce 500 (medium) or 700 (bold) — existing `Label` component's `font-medium` (500) default is overridden to 600 for this phase's admin/config-heavy screens for stronger visual hierarchy against dense tables.

## Color

Existing neutral shadcn theme (`resources/css/app.css` `:root` / `.dark`) is monochrome — accent and dominant/secondary all derive from the same near-black/white/gray scale, not a separate hue. Contract below maps the 60/30/10 split onto those existing tokens; no new colors introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`hsl(0 0% 100%)` light / `hsl(0 0% 3.9%)` dark) | Page background, main content canvas across all 7 portals |
| Secondary (30%) | `--card` / `--sidebar` / `--muted` (`hsl(0 0% 98%)` / `hsl(0 0% 96.1%)`) | Sidebar nav, card containers, table zebra-striping, config section panels |
| Accent (10%) | `--primary` (`hsl(0 0% 9%)` light / `hsl(0 0% 98%)` dark) | Reserved for: primary submit buttons ("Save Configuration", "Log In"), active sidebar nav item indicator, focus rings, links (`TextLink.vue`) |
| Destructive | `--destructive` (`hsl(0 84.2% 60.2%)`) | Reserved for: "Deactivate Account" confirm button, account-locked-out status badge, failed-login-attempt indicator in audit trail, session-timeout/kicked-out alert banners |

Accent reserved for: primary form submit buttons, active nav indicator, focus states, hyperlinks only. Never used for decorative fills, illustrations, or as a general "highlight" color on non-interactive elements.

## Phase-Specific UI Notes

**Dedicated portal pattern (locked architecture decision, not open for reconsideration):** Each of the 7 roles (Owner, Admin, Frontline Staff, Artist, Cashier, Production Staff, Accounting Staff) gets its own portal — not a shared layout with role-filtered nav. Reuse the existing `AppSidebarLayout.vue` / `AppSidebar.vue` shell per role, but each role's Vue pages live under their own `resources/js/pages/{role}/` namespace with a role-specific nav item set passed into the sidebar (not a single shared nav array filtered at runtime). Owner and Admin are the only roles that see User Management, System Configuration, and Audit Trail in their nav for this phase; the other 5 roles land on a portal home with no nav items yet (populated in later phases).

**403 boundary page:** Build a dedicated Inertia error/response for role-boundary violations (not the framework's generic 403 blade page) so it matches the app shell — reuse `AuthLayout`-style centered card, `AlertError.vue` if suitable, with the copy above and a single "Return to your dashboard" `TextLink`.

**Audit trail table:** Read-only. Columns: timestamp, actor (user), role, action, target/entity, IP address (if captured). Filters: user (select/search), action (select), date range (two date inputs or a range picker — no calendar range component installed yet; use two plain `Input[type=date]` fields for this phase rather than adding a new registry dependency). No row-level edit/delete controls — omit the actions column entirely rather than disabling buttons.

**Lockout/session state feedback:** Login form (`Login.vue`) needs a visible state for "account locked" distinct from "wrong password" — use an `Alert` (destructive variant) above the form, not just an inline `InputError`, since this is an account-level state, not a field-level validation error.

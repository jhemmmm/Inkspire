<threat_model>

## Trust Boundaries

| Boundary                                      | Description                                                                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Direct URL navigation -> owner-only routes    | A non-owner/admin user typing `/owner/dashboard` directly must be blocked server-side, not merely lack a nav link to it                     |
| Fortify login pipeline -> role-based redirect | The redirect target is derived from the authenticated user's own `role` column (trusted, server-resolved), never from client-supplied input |

| T-01-01         | Elevation of Privilege | `routes/owner.php`, `app/Http/Middleware/EnsureUserHasRole.php` | mitigate    | Every owner-only route is wrapped in a `role:owner,admin` middleware group applied at the route-group level (not per-controller-method), verified by `tests/Feature/RoleBoundaryTest.php` hitting the route directly as a wrong-role user and asserting 403 — never relies on hidden nav (Pitfall 4) |
| T-01-03         | Spoofing/Tampering     | Fortify's `PrepareAuthenticatedSession` (unmodified)            | accept      | Session-fixation protection (session ID regeneration on login) is Fortify's existing, unmodified behavior; this plan's custom `LoginResponse` only changes the redirect target after authentication succeeds, never touches session handling                                                         |

<objective>
Wire Laravel's native `Illuminate\Auth\Events\Login`/`Logout` events (already fired by Fortify's unmodified pipeline, per D-02) into the audit trail substrate built in Plan 01-01, and capture the winning session's ID on the user row so Plan 01-08's `VerifySingleSession` middleware has something to compare against.

Purpose: D-02 mandates auth events be captured separately from Eloquent mutations via native Laravel auth events, not by touching Fortify's own controllers. This plan is the first of two "auth event -> audit" plans (Plan 01-07 handles Failed/Lockout).
Output: `HandleSuccessfulLogin`/`HandleLogout` listeners (auto-discovered by Laravel's event-listener discovery — no manual registration needed in this Laravel 13 app), each writing to `audit_trail` via the shared `AuditLogger`.
</objective>

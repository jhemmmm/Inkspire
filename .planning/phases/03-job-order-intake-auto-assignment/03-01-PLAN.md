## Phase Goal

**As a** Frontline Staff member, **I want to** have each job order I create automatically validated (when it needs a print-ready file) or automatically routed to an available Artist (when it needs consultation), **so that** every job order becomes a real, production-ready record without any manual validation or assignment step.

<objective>
Build the backend half of Phase 3's vertical slice: Type A file validation (JOB-01) and Type B round-robin artist assignment (JOB-02) both run synchronously, in the same request that already creates the job order, and both write their outcome directly onto the `job_orders`/`users` rows the frontend (Plan 03-02) will render. This plan is deliberately backend-only — two independent-but-file-adjacent action classes (`ValidateJobOrderFile`, `AssignArtistToJobOrder`), two new migrations, and the controller wiring that calls both from the exact same `QueueEntryController::addJobOrder()`/`store()` call sites are one tightly-coupled unit of business logic (D-01 through D-09) that cannot be safely split across parallel plans without one plan re-editing the other's diff of the same controller methods and the same `JobOrderStatus` enum file. Combining this with the UI wiring in one plan would also push a single agent well past a safe context budget — the same context-cost reasoning Plan 02-02 documented for this exact backend/frontend split. Plan 03-02 (next, same wave-chain) wires the UI on top of the endpoints and eager-loaded props this plan ships, completing the user-observable slice.

Purpose: JOB-01/JOB-02 both hinge on correctness properties that are easy to get subtly wrong under concurrency or partial failure — a raster DPI read must never crash on a malformed upload, and two simultaneous Type B job orders must never race onto the same artist. Proving both with dedicated Pest coverage before any UI depends on them is the point of this plan.
Output: Two additive migrations, three new `JobOrderStatus` enum cases, `ValidateJobOrderFile` + `AssignArtistToJobOrder` action classes, the `QueueEntryController` wiring that calls both from `addJobOrder()`/`store()`, a new `JobOrderController::replaceFile()` endpoint, and Pest coverage for every outcome branch (pass, fail-by-format, fail-by-size, fail-by-DPI, assigned, unassigned, replace-file).
</objective>

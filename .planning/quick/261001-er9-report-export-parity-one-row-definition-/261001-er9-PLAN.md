# Quick Task 261001-er9: Report export parity — one row definition feeds PDF and Excel

Source: `let-s-create-a-plan-twinkly-breeze.md`, section "1. Report export parity" ONLY. Sections 2-5 (Job Orders/Audit Trail exports, profile pictures, search/filters, responsive layout) are separate later quick tasks — out of scope here.

Root cause: every report is formatted twice — once per cell in `resources/views/reports/{key}.blade.php`, once in `ReportExportController::xlsxRowValues()`, which writes raw values. That's why Production Status shows Urgency as "Rush" in PDF but "TRUE" in Excel. Fix: one row-shaping method and one rendering pair (`TableExport::pdf()`/`xlsx()`) feed both formats, so they cannot drift again.

Locked (do not revisit): the urgency RULE is unchanged — `ReportBuilder::productionStatusRows()` still computes urgency from the due date alone. `ReportBuilder`, `ReportController`, and `ReportsWorkspace.vue` are untouched. No frontend files change in this task.

## Task 1: `TableExport` support class + generic `table.blade.php` view

**Files:** `app/Support/TableExport.php` (new), `resources/views/reports/table.blade.php` (new)

Create the class with `php artisan make:class Support/TableExport --no-interaction`, then implement it as `final class TableExport` with no instance state (same static-utility shape as `App\Support\AuditLogger`), exposing exactly two `public static` methods sharing one identical argument list:

`pdf(string $title, array $headings, array $rows, array $moneyColumns, ?array $meta, ?array $totalRow, string $filename): \Symfony\Component\HttpFoundation\Response`
`xlsx(string $title, array $headings, array $rows, array $moneyColumns, ?array $meta, ?array $totalRow, string $filename): \Symfony\Component\HttpFoundation\StreamedResponse`

Argument contract (document with full PHPDoc array-shape annotations — Larastan level 7 requires them for these mixed-type arrays, matching the style already in `ReportExportController`'s docblocks):

- `$headings` — `list<string>`, column labels in display order.
- `$rows` — `list<list<\Carbon\CarbonInterface|null|float|int|string>>`. Cells arrive display-ready EXCEPT for the two deliberate per-format differences this class owns: money-column cells (0-based indexes listed in `$moneyColumns`) and `CarbonInterface` cells. No `bool` and no raw snake_case enum string may ever appear here — the caller resolves those to a final label before calling either method.
- `$moneyColumns` — `list<int>`, 0-based indexes into `$headings`/every row that are money.
- `$meta` — `?array{from?: \Carbon\CarbonInterface, to?: \Carbon\CarbonInterface, generatedAt?: \Carbon\CarbonInterface, generatedBy?: string}`. `pdf()` merges this directly into the view data so `reports.layout`'s existing `@isset($from, $to)` / `@isset($generatedAt, $generatedBy)` blocks keep working unchanged. `xlsx()` accepts `$meta` for signature parity only — no header/range row exists in the sheet today, so it goes unused there; same reasoning applies to `xlsx()`'s unused `$title`.
- `$totalRow` — `?list<\Carbon\CarbonInterface|null|float|int|string>`, one cell per heading, or `null` when the report has no total row.
- `$filename` — base name with no extension (`pdf()` appends `.pdf`, `xlsx()` appends `.xlsx`), matching the existing `"{reportKey}_{from}_{to}"` pattern used today.

`pdf()`: merge `['title' => $title, 'headings' => $headings, 'rows' => $rows, 'moneyColumns' => $moneyColumns, 'totalRow' => $totalRow]` with `$meta ?? []` into one `$data` array, then `Pdf::loadView('reports.table', $data)->setOption('isPhpEnabled', true)->download("{$filename}.pdf")` — identical construction to today's `exportPdf()`, just pointed at the new generic view.

`xlsx()`: move the existing `response()->streamDownload()` / openspout `Writer` block here verbatim — keep `openToFile('php://output')` inside the `streamDownload` closure, never the writer's browser-direct method (see `ReportExportController::exportXlsx()`'s current docblock for why: output must never start streaming before the audit write lands). Before building `$sheetRows`, run `$rows` (and `$totalRow`, if not null) through a private `xlsxCells(array $row, array $moneyColumns): array` helper that, per cell in order: passes `null` through unchanged; calls `->toDateString()` on a `CarbonInterface`; casts `(float)` a value at a `$moneyColumns` index; otherwise passes the value through unchanged. `$sheetRows = [$headings, ...converted $rows, ...converted $totalRow if present]`.

Create `resources/views/reports/table.blade.php`, `@extends('reports.layout')`, replacing all four deleted per-report views (Task 2) with one generic table. Keep the `@if (empty($rows)) <p class="empty-state">No records for this range.</p> @else ... @endif` wrapper the four existing views already use. Render `$headings` as `<th>` cells, adding class `money` on indexes present in `$moneyColumns` (matches `reports.layout`'s existing `.money` CSS). For each `$rows` row render one `<td>` per cell in the same order: `null` → em dash `—` (matches `expenses.blade.php`'s and `production-status.blade.php`'s existing null handling); `instanceof \Carbon\CarbonInterface` → `->format('M j, Y')`; a `$moneyColumns` index → `₱` + `number_format((float) $value, 2)` (matches the four existing views' peso formatting byte-for-byte); otherwise the raw value via `{{ }}`. Check `null` before the `CarbonInterface`/money checks so a nullable date (production-status's `Due`) renders as the dash, not a crash. When `$totalRow` is not `null`, render one more `<tr>` after the data rows using the same per-cell rules, wrapped in `<strong>` (null cells stay blank, not dashed).

No caller exists yet this task — verify with static analysis only: `vendor/bin/pint --dirty --format agent` then `composer types:check`.

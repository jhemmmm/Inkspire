# Quick Task 261001-i4q: Search and filters on the other-portal pages

Source: `let-s-create-a-plan-twinkly-breeze.md`, section "4. Search and filters", **PART B** — the four non-admin pages left over from `261001-he2` (Part A, done): `accounting-staff/AccountsReceivable/Index.vue`, `accounting-staff/Expenses/Index.vue`, `cashier/Dashboard.vue`, `production-staff/Dashboard.vue`. Section 5 (container queries) is a later, separate task.

Goal: staff on these four screens can type to find a row and narrow the list with a filter, exactly like Part A's admin pages. Every list here already arrives whole from the server, so this is entirely client-side — **no new requests, no controller changes, no new Inertia props.**

Locked decisions are numbered 1-10 below; task text cites them inline as `(D1)`...`(D10)`. Do not revisit a locked decision.

1. Reuse `useTableFilter.ts` and `TableFilterBar.vue` exactly as Part A's pages use them (`resources/js/pages/admin/CreditRequests.vue`, `resources/js/pages/admin/UserManagement.vue` are the reference usages). One search box per page.
2. **Compose with what is already there — do not replace it.** `AccountsReceivable/Index.vue` has an aging-bracket tab filter (`activeFilter` / `filteredRows`) and `production-staff/Dashboard.vue` has a stage tab filter (`activeFilter` / `filteredJobOrders`) — both built on the `Tabs` primitive. Keep those tabs, their counts, and their behaviour exactly as they are. The new search box and any new filter control apply ON TOP of the tab filter (logical AND): the tab narrows first, then search/filter narrows what's left. "Clear filters" resets the tab back to "All" too. The `StatCard` tiles above both tables keep describing the whole open/production set, never the filtered view — a short comment marks this as intentional on both pages.
3. Per-page search fields and new filter(s) — see the table in each task below. No second bracket/stage control is added anywhere; the existing tabs are the only bracket/stage filter.
4. **Totals that are money stay honest.** `Expenses/Index.vue`'s `total`/`activeCount`/`voidedCount` and `AccountsReceivable/Index.vue`'s bracket `StatCard` totals are server-computed over the whole range/list (`ExpenseController::index`, the `bracketSummaries` prop) and must keep being read straight from props — never recomputed from a filtered array. `production-staff/Dashboard.vue`'s `stageCounts` tiles are the same principle applied to a client-derived count: they must keep summing `props.jobOrders`, not the filtered list. Only `TableFilterBar`'s "Showing X of Y" speaks for the filtered view.
5. **Two distinct empty states**, everywhere: the page's existing "nothing here at all" state stays exactly as-is; "rows exist but none match" is a new `EmptyState` titled "No matches" with a "Clear filters" action. On `cashier/Dashboard.vue`, which renders two independent section tables (rush / regular), each section keeps its own two-tier empty state and its `SectionHeading` stays visible even when that section's filtered result is empty.
6. Row actions (Process Payment, Check Payment Status, Cancel Job Order, View Receipt, Advance/Send Back a stage, Edit/Void an expense, View Entry) keep working on filtered rows — they read the real row object from the filtered array, so this needs no special handling, same as Part A (D5 there).
7. Any select that can exceed ~10 options uses `SearchableSelect`; everything else uses the plain `Select` already imported on each page. One consistent control style per page.
8. Do not touch viewport grid classes (`grid-cols-*` etc.) on any of these four pages — that is section 5, a later task.
9. Do not touch the artist dashboard, the accounting dashboard, the frontline pages, or any admin page. No new dependencies. Do not hand-edit generated files under `resources/js/routes/**` or `resources/js/actions/**`.
10. This app server-renders in dev: never touch `window`, `document`, or `location` during setup or render (none of the work below needs to).

Before editing, go through `/gsd-quick`. No `.ai/rules` directory exists in this repo. Load the `inertia-vue-development` and `tailwindcss-development` skills as you touch these files — this task has no backend changes, so `laravel-best-practices`/`testing-best-practices` don't apply, and `wayfinder-development` isn't needed since no route/action call changes.

There is no JS unit-test framework in this project and none may be added (`useTableFilter.ts`'s pure matcher is already verified by Part A's Task 1 and is not touched here). Everything in this task is confirmed by the orchestrator afterward in a real browser, per `CLAUDE.md`'s "UI Changes Require a User-Friendly Check".

    const statuses = Array.from(

            label: COLLECTION_STATUS_LABELS[status] ?? status,

const collectionStatusFilter = ref(ALL);

/**
 * Search + the new Collection status filter apply ON TOP of the existing
 * bracket/closed tab filter (D2) — `filteredRows` (the tab layer) is the
 * input here, not `props.receivables` directly.
 */
const { searchTerm, filtered: visibleRows } = useTableFilter(
    () => filteredRows.value,
    (row) => [
        row.job_order.number,
        row.job_order.queue_entry.customer?.name,
        row.job_order.description,

            (row) =>

                row.collection_status === collectionStatusFilter.value,

        collectionStatusFilter.value !== ALL ||
        activeFilter.value !== 'all',

    searchTerm.value = '';
    collectionStatusFilter.value = ALL;

const ALL = 'all';

/**
 * Starts from the Admin-managed category list (System Configuration) and
 * appends any category still present on a row but no longer configured —
 * so a renamed/removed category doesn't silently vanish from the filter
 * for rows still carrying the old value (D3).
 */
const categoryOptions = computed<SearchableOption[]>(() => {
    const configured = new Set(props.categories);
    const extra = Array.from(
        new Set(props.rows.map((row) => row.category)),
    ).filter((category) => !configured.has(category));

    const all = [...props.categories, ...extra].sort((a, b) =>
        a.localeCompare(b),
    );

    return [
        { value: ALL, label: 'All categories' },
        ...all.map((category) => ({ value: category, label: category })),
    ];
});

const categoryFilter = ref(ALL);

const statusFilterOptions = [
    { value: ALL, label: 'All statuses' },
    { value: 'active', label: 'Active' },
    { value: 'voided', label: 'Voided' },
];

const statusFilter = ref(ALL);

const { searchTerm, filtered: filteredRows } = useTableFilter(
    () => props.rows,
    (row) => [row.description, row.category, row.recorded_by],
    {
        filters: [
            (row) =>
                categoryFilter.value === ALL ||
                row.category === categoryFilter.value,
            (row) => {
                if (statusFilter.value === ALL) {
                    return true;
                }
                return statusFilter.value === 'voided'
                    ? row.voided_at !== null
                    : row.voided_at === null;
            },
        ],
    },
);

const filtersActive = computed(
    () =>
        searchTerm.value.trim() !== '' ||
        categoryFilter.value !== ALL ||
        statusFilter.value !== ALL,
);

function clearFilters(): void {
    searchTerm.value = '';
    categoryFilter.value = ALL;
    statusFilter.value = ALL;
}

## Context

Five code-review bugs, already investigated and designed by the orchestrator — implement as
specified, do not redesign.

**Bugs 1+2+3 share one root cause:** "can the price still change?" is answered differently in
four places today — the PayMongo path and the credit-request path both test
`total_amount === null`, the Cash path and `SavePricingAndPaymentRequest` both test "no
transactions exist", and none of the four locks an Admin-approved On-Credit order (which has
`payment_status` `OnCredit`, a real `AccountsReceivable` row, and zero `Transaction` rows, since
the credit line itself is never a `Transaction`). The fix is one shared predicate,
`JobOrder::pricingIsEditable(): bool`, used everywhere that question is asked.

**Bug 4:** `ValidateJobOrderFile` ignores the intake `width_ft`/`height_ft` a customer's custom
size was recorded at, falling back only to the `print_size` catalog preset lookup — so a
custom-dimension Type A order with no matching preset skips the effective-DPI check entirely.

**Bug 5:** `Admin\DashboardController::unpaidBalances()` counts written-off job orders as
outstanding money, inflating both the dashboard's unpaid count and its outstanding-amount tile.
